# Environment variables

Generated by `vpd env` from the code. Print the same list from the image with:

```bash
docker run --rm ntuxa76/sip-source:0.6 env
```

## How to set them

- **Docker Compose:** add them under `environment:` of the `sip-source` service in `docker-compose.yml`, or put them in `.env` and reference them there.
- **docker run:** pass each one with `-e NAME=value`.
- **Secrets:** the passwords below also accept a `_FILE` variant, for example `VP_DB_PASSWORD_FILE=/run/secrets/db`, which reads the value from that file.

Only `VP_DB_HOST`, `VP_DB_USER` and `VP_DB_PASSWORD` are required. Everything else has a working default.

Storage isn't set here. Captured data goes to the built-in Local file storage under `VP_DATA_DIR` until you add a ClickHouse server under **Admin → Storage**.

## Startup settings

Read once when the container starts. Changing one means restarting the container.

### Database

| Variable | Default | Required | Description |
|---|---|---|---|
| `VP_DB_HOST` | – | yes | MariaDB host name or IP. |
| `VP_DB_USER` | – | yes | MariaDB user. |
| `VP_DB_PASSWORD` | – | yes | MariaDB password. VP_DB_PASSWORD_FILE reads it from a file instead (Docker secrets). |
| `VP_DB_NAME` | `voip_panel` | no | Database name. It must already exist; the tables are created on first start. |
| `VP_DB_PORT` | `3306` | no | MariaDB port. |
| `VP_DB_URL` | – | no | Replaces all VP_DB_* above, e.g. mysql://user:pass@host:3306/voip_panel. VP_DB_URL_FILE also works. |
| `VP_DB_SSL_MODE` | `preferred` | no | disabled, preferred, required, verify_ca or verify_identity. |
| `VP_DB_MAX_CONNECTIONS` | `10` | no | Connection pool size. |
| `VP_DB_CONNECT_RETRIES` | `60` | no | Attempts to reach MariaDB at startup before giving up. |
| `VP_DB_CONNECT_RETRY_SECONDS` | `2` | no | Wait between those attempts. |

| `VP_LOCAL_PORT` | `8124` | no | Port on 127.0.0.1 the Local file storage engine listens on inside the container. |

## Application settings

These can also be changed under **Admin → Settings**, where they are saved in MariaDB. A value set here takes priority over the saved one and shows as locked on that page. An invalid value stops the container at startup with a message naming the variable.
